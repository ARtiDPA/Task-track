# Ritmo — трекер привычек

Личный трекер на русском языке: привычки, ежедневные отметки, серии, статистика, годовая карта активности и достижения.

## Запуск

Полный запуск в Docker:

```powershell
docker compose up -d --build --wait
```

Открыть http://localhost:5173. Структура проекта и команды проверки описаны в [ARCHITECTURE.md](ARCHITECTURE.md), подробности восстановления данных — в [DOCKER.md](DOCKER.md).

Для запуска сервера вне Docker нужны Python 3.10+ и Redis. Из папки проекта:

```powershell
python -m pip install -r requirements.txt
docker compose up -d redis
python -m backend.app.main
```

Затем откройте http://localhost:5173.

Сервер автоматически создаёт SQLite-базу `data/ritmo.sqlite3` и ключ подписи `data/jwt-secret`. Redis слушает только `127.0.0.1:6379`, имеет проверку здоровья и постоянный Docker volume. Прямое открытие `index.html` или `python -m http.server` не подходит: приложение работает через API.

При первом входе создайте профиль. У первого аккаунта есть явная опция переноса прежних привычек из старой общей базы. Данные сохраняются в старых таблицах и не теряются, если перенос не выбран. Следующие профили начинают с отдельных привычек и не получают чужую историю.

## Профили и сессии

- Регистрация по имени, email и паролю (от 10 до 128 символов), вход и выход.
- Пароли хешируются scrypt с индивидуальной случайной солью.
- Access JWT (HS256) действует 15 минут и хранится только в памяти вкладки.
- Refresh-токен — HttpOnly, SameSite=Strict cookie; он обновляется при использовании. Сессии в Redis живут до 30 дней. Выход отзывает сессию, включая уже выданные JWT.
- Все операции с привычками проверяют владельца на сервере. Одинаковые идентификаторы привычек разных пользователей не конфликтуют.
- Ограничение частоты входа и регистрации хранится в Redis; при его недоступности доступ закрыт с ошибкой 503.
- `REDIS_URL` меняет адрес Redis. `JWT_SECRET` (минимум 32 байта) позволяет указать собственный ключ. Для HTTPS включите `RITMO_COOKIE_SECURE=1`. По умолчанию сервер доступен только локально по HTTP.

## Возможности

- Добавление, редактирование и удаление привычек с выбором цвета и значка.
- 72 значка в 6 категориях с поиском по названию.
- Отметки за текущую неделю; будущие дни и дни до создания привычки заблокированы.
- Текущие и лучшие серии, показатели за неделю и месяц, график выполнения.
- Карта активности за последние 365 дней с фильтром по привычке.
- Достижения за реальные результаты, анимации и конфетти за идеальный день.
- 28 достижений за серии, выполненные привычки, активные и идеальные дни, водный ритм — с прогрессом и фильтрами.
- Отдельный трекер воды: профиль с ростом и весом, настраиваемая цель, стаканы 100/250/500 мл, история и отмена записей.
- Анимированный силуэт человека справа, который заполняется по мере достижения цели; волны, пузырьки и плавное изменение уровня.
- Личные финансы: доходы, расходы, начальный остаток, категории, месячные лимиты, графики и CSV-экспорт.
- Адаптивная вёрстка, управление с клавиатуры, поддержка уменьшенного движения.
- Сохранение привычек, их даты создания, значков и цветов в SQLite.
- Сохранение статуса выполнения на каждую дату, включая отменённые отметки.
- Проценты учитывают только дни с момента создания каждой привычки.
- Перенос прежней общей SQLite-базы в первый профиль по явному выбору при регистрации.

Начальные привычки — примеры, без выдуманных выполнений. Существующая база никогда не перезаписывается старым кешем. Если у старой привычки нет даты создания, используется её самая ранняя отметка, а при отсутствии отметок — дата переноса.

Каждый профиль видит только свои данные, в том числе при входе из другого браузера. Данные переживают перезапуск сервера и очистку браузера. Каталог `data/` исключён из Git. Для резервного копирования остановите сервер и скопируйте каталог `data/`, включая ключ подписи. Другой путь можно указать через `python -m backend.app.main --database путь/к/базе.sqlite3`, другой порт — через `--port 5174`.

При ошибке сохранения интерфейс не применяет изменение и показывает сообщение; действие можно повторить. Привычки и токены не записываются в общий localStorage браузера. Шрифт Manrope загружается из Google Fonts; при отсутствии сети используется системный шрифт.

## Трекер воды

Настройка при первом открытии просит рост, вес и подтверждение совершеннолетия. Стартовая цель — 7 стаканов по 250 мл (1 750 мл), её можно заменить своей. Это удобный общий ориентир для учёта напитков, а не медицинская норма и не формула по росту и весу. Точную индивидуальную потребность только из этих двух параметров определить нельзя. Основа пояснения — [рекомендация NHS о 6–8 стаканах жидкости](https://www.nhs.uk/live-well/eat-well/food-guidelines-and-food-labels/water-drinks-nutrition/); размер стакана 250 мл выбран самим приложением. Пояснения о роли воды основаны на [CDC](https://www.cdc.gov/healthy-weight-growth/water-healthy-drinks/index.html).

Рост, вес, настройки и записи доступны только владельцу профиля. Цели сохраняются по датам: изменение сегодняшней цели не переписывает результаты предыдущих дней. Новый день начинается с нуля, история остаётся. Уровень силуэта отображает процент выбранной цели, а не физиологическую гидратацию. Достижения не награждают за питьё сверх цели. Каждая запись имеет идентификатор: повтор после потери ответа не дублирует выпитый стакан.

## Финансы

Откройте «Финансы» в боковом меню. В «Остаток и лимит» укажите деньги, которые были **до первой внесённой операции**. После этого добавляйте доходы и расходы. Операции можно изменять и удалять, выбирать даты в прошлом, добавлять свои категории и искать записи. Все данные изолированы по профилям и хранятся в SQLite; банковские счета автоматически не подключаются.

- «Доступно сейчас» = начальный остаток + все доходы − все расходы по всей истории.
- Доходы, расходы, итог, круговая диаграмма и лимиты относятся к выбранному месяцу. График баланса учитывает остаток, накопленный до его начала.
- Общий месячный лимит и лимиты категорий — повторяющиеся настройки для анализа каждого месяца. Их изменение не меняет операции и не означает списание денег.
- Доступная сумма в день = неотрицательный минимум свободного баланса (без копилок) и остатка месячного лимита, делённый на число оставшихся дней с сегодняшним включительно. Без лимита используется свободный баланс. Будущие доходы не предполагаются; для завершённых месяцев дневной показатель не рассчитывается.
- Прогноз расходов — простое продолжение среднего дневного темпа выбранного текущего месяца, а не обещание будущего результата.
- Деньги передаются и считаются в целых копейках. В интерфейсе и CSV — рубли; до двух знаков после запятой. Повтор сохранения с тем же идентификатором не дублирует операцию.
- Экспорт выгружает все операции выбранного месяца (поиск и фильтр категории не ограничивают выгрузку).

### Копилки и долги

Во «Финансах» появились вкладки «Копилки», «Долги» и «Планирование».

- Копилка хранит название цели, тип (покупка/подарок или сейф), целевую и накопленную суммы, место хранения (наличные, банк, другое) и название счёта/места. Суммы по одинаковым местам суммируются. Это учёт денег в копилках, не банковские выписки по всем счетам.
- Деньги копилок **уже входят** в общий остаток: начальный остаток финансов должен включать и их. Пополнение резервирует свободные деньги, возврат освобождает их; доходы/расходы при этом не создаются. Дневной бюджет не расходует зарезервированную сумму.
- Для покупки после достижения цели есть кнопка «Купил». Фактическая стоимость создаёт ровно один расход; неиспользованный остаток освобождается. Отмена покупки убирает этот расход и возвращает прежнюю сумму в копилку. Сейф не требует покупки или завершения.
- Долги поддерживают «я должен» и «мне должны»: сумма, человек/банк, ближайшая дата и сумма платежа, комментарий. Кнопка «Закрыл долг» записывает остаток как полный платёж. Закрытые долги сохраняются в истории.
- Галочка учёта платежа в финансах позволяет создать расход/доход. Если он уже внесён вручную, её нужно снять. Частичные платежи уменьшают остаток и ближайший платёж. Для разового графика после выполнения ближайшего платежа без указанной следующей даты дата очищается. Для ежемесячного графика укажите число месяца (1–31), первый платёж и регулярную сумму: после оплаты дата переносится автоматически. В коротком месяце используется последний день, затем исходное число восстанавливается. Платёж сверх ближайшего взноса погашает следующие взносы по порядку; последний ограничен остатком долга.
- Для копилки можно настроить прогноз: сумму регулярного взноса, частоту (день, неделя, месяц) и дату первого взноса. На карточке и в форме появятся дата достижения цели, число взносов, последний неполный взнос и график. Расчёт использует фактически накопленную сумму, пропускает прошедшие даты и не начисляет проценты. Взносы отмечаются вручную кнопкой «Пополнить»; настройка прогноза сама не перемещает деньги.
- Платёж можно отменить из истории. Для ежемесячного графика отмена доступна с последнего платежа, чтобы сохранить последовательность дат. При отмене последнего платежа восстанавливается прежняя ближайшая дата и сумма платежа. Связанные финансовые операции редактируются/отменяются через их копилку, долг или план, чтобы суммы не расходились.

### Планы и бюджет до даты

Будущие доходы и расходы добавляются кнопками «Ожидаемый доход» / «Плановый расход» на обзоре финансов, в «Планировании» или прямо на выбранный день календаря с суммой, категорией и датой. Они не меняют фактический баланс. «Провести» создаёт одну фактическую операцию выбранной датой не позднее сегодняшней и исключает план из прогноза. Проведение можно отменить; отменённые планы восстановить.

Калькулятор считает от сегодня до выбранной даты включительно, до года вперёд. Есть кнопки недели, 30 дней и конца месяца. Он показывает дневной, недельный и общий равномерный бюджет, ожидаемый остаток и график. Из фактического остатка вычитаются копилки, затем по датам учитываются выбранные планы и ближайшие платежи по долгам. Включение ожидаемых доходов и долгов можно отключить. Для ежемесячного долга учитываются все взносы до выбранной даты, суммарно не больше остатка долга; для разового — ближайший платёж. Долги без даты показываются отдельно как не включённые.

Дневная сумма ограничивается минимальным отношением ожидаемого свободного остатка к числу прошедших дней периода. Так положительный итог после зарплаты не скрывает нехватку денег до неё. Планы условно исполняются в начале дня, а непроведённые планы с прошедшими датами считаются ожидающими сегодня. Месячные лимиты не являются расходами и повторно не вычитаются. Не следует дублировать ближайший платёж по долгу отдельным планом.

### Календарь

Отдельная вкладка показывает месяц и список событий выбранного дня. Можно добавлять, редактировать и удалять события с названием, датой, необязательным временем и заметкой. Кнопки «Доход в этот день» и «Платёж в этот день» создают финансовый план с выбранной датой. Плановые операции и все ежемесячные платежи открытых долгов появляются автоматически; из них можно перейти в финансы. Данные календаря, как и копилки, долги и планы, доступны только владельцу профиля.

## План дня

Отдельная вкладка «План дня» хранит задачи с заметками, приоритетом, датой и необязательным временем. Есть список без даты, выбор дня/недели, выполнение с отменой, поиск и список просроченных дел для переноса. Назначение даты автоматически показывает ту же задачу в общем календаре. Из календаря можно создать, изменить, выполнить или удалить задачу и открыть выбранный день в планировщике. Копии событий не создаются: оба экрана работают с одной записью. Данные изолированы по профилям и сохраняются в SQLite.

У каждой задачи есть чеклист до 100 шагов с отдельными отметками и прогрессом. Чеклист редактируется в форме задачи и доступен прямо в календаре. Завершение родительской задачи закрывает все её пункты; снятие отметки с пункта возвращает задачу в работу. Кнопка «Фокус» переносит название задачи в таймер перед запуском сессии.

## Фокус

Отдельная вкладка с таймером на 1–180 минут, пресетами 5/25/50/90 минут, паузой, продолжением, досрочным сохранением и отметкой отвлечения. Сервер хранит активную сессию и интервалы работы: перезагрузка не сбрасывает время, паузы не учитываются, счёт останавливается на выбранной длительности. Сессия, закончившаяся при закрытой странице, сохраняется при следующем обращении к серверу. Одновременно у профиля может быть одна активная сессия.

Своя длительность задаётся в отдельном поле минут. При достижении выбранного времени звучит короткий сигнал из трёх нот. Он планируется на аудиочасах браузера; пауза и отмена снимают запланированный сигнал, продолжение назначает его заново. Повторные обновления статистики не проигрывают сигнал повторно. Кнопка «Проверить звук» позволяет проверить громкость. После перезагрузки браузер может потребовать нажатие этой кнопки для разрешения звука в новой вкладке; закрытая страница сигнал не воспроизводит.

Переключение вкладок, окон и работа в других приложениях не ставят фокус на паузу и не считаются отвлечением. Пауза и отметка отвлечения включаются только вручную. Таймер идёт на сервере до выбранного лимита, в том числе при закрытой странице. Это учёт собственных фокус-сессий, а не измерение использования TikTok или других программ.

Есть дневная цель, графики за 7 и 30 дней, карта 90 дней, серия дней от минуты фокуса, общая длительность, лучшая сессия и история последних 100 сессий. В сводных показателях и графиках учитывается вся история. Интервалы, пересекающие полночь, разделяются по дням Москвы. Удаление сессии удаляет её время из статистики. Данные доступны только владельцу профиля.

## Мой вишлист

Личный список желаний с ценой, ссылкой, категорией, описанием и приоритетом. Доступны поиск, фильтры категорий и статусов, сортировка по цене/приоритету/новизне, отметка «Сбылось» с отменой и список «На потом». Неизвестная цена отличается от нулевой. Вишлист хранится в профиле отдельно от подарков в «Личной жизни»; отметки не создают финансовые операции.

## Личная жизнь

Отдельная вкладка для заметок о предпочтениях партнёрши, подарков с ценами и ссылками, идей свиданий с местом и бюджетом, знаков внимания и воспоминаний. Записи можно искать, закреплять, изменять и удалять. Для подарков и свиданий есть фильтр статуса и цены: неизвестная цена отличается от нулевой и не попадает в подбор по бюджету.

В «Планировщике» расположен **отдельный личный календарь**, со своими планами и важными датами. Выберите день, добавьте свидание, подарок, знак внимания или повод; можно указать время, место и бюджет. Видны суммы на день и месяц, отдельно отмечены планы без цены. Важные даты могут повторяться ежегодно; 29 февраля в обычном году приходится на 28 февраля. В настройках вашей истории можно сохранить имя и дату начала отношений — для счётчика дней вместе и автоматической годовщины. Общий календарь финансов и событий не заполняется этими записями.

Дополнительно: случайный выбор ещё не запланированного свидания из своих идей по бюджету, вопросы для разговора с сохранением ответа в заметку и список ближайших поводов на 30 дней. Цены служат ориентиром, а отметки «Подарил» / «Сходили» не создают финансовые операции. Данные сохраняются в SQLite и изолированы по профилям.

Трекер показывает дату и число дней с последнего подарка, свидания и маленькой заботы. Можно быстро отметить событие сегодня или задним числом и отменить ошибочную отметку в истории. Выполнение записи из списка добавляет событие в трекер, отмена выполнения убирает его. Фактическая дата хранится отдельно от даты плана и редактируется в выполненной записи. Будущие планы не считаются состоявшимися событиями. Прежние отметки выполнения переносятся при обновлении базы.

## Проверка

Проверка API, JWT/Redis, изоляции профилей, расчётов и пользовательских сценариев. Нужен запущенный Redis. Проверки используют временные SQLite-базы и отдельные случайные префиксы Redis; реальные данные и сессии не меняются:

```powershell
python -m pip install -r requirements-dev.txt

python -m unittest discover -s tests -p "test_*.py" -v

```
