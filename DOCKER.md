# Локальный запуск

Открыть http://localhost:5173 и войти с прежними учётными данными.

Из каталога проекта:

```powershell
docker compose up -d --build --wait
docker compose ps
docker compose logs --tail 50 app
docker compose stop
```

Контейнеры перезапускаются автоматически через `restart: unless-stopped` при работающем Docker Desktop.

## Восстановление 27.10.2026

Имена файлов исходной копии перепутаны: `Dump/SHA256.txt` содержит PostgreSQL custom dump версии 17, `Dump/ritmo.dump` — инструкцию, `Dump/RESTORE.txt` — переменные окружения, `Dump/download` — ключ JWT.

Дамп восстановлен в PostgreSQL 17, в отдельный постоянный Docker volume. Исходная копия не изменена.

Код этой версии приложения поддерживает SQLite. Все 413 записей из 31 таблицы перенесены в `data/ritmo.sqlite3` с проверкой каждого поля, количества записей и внешних ключей. Дополнительные столбцы и служебные таблицы сохранены. Копия экспорта находится в `data/postgres-export.json`, описание столбцов — в `data/postgres-schema.json`. Скрипт `restore_sqlite.py` предназначен для восстановления в новую SQLite-базу и отказывается перезаписывать существующую.

**Рабочая база приложения — `data/ritmo.sqlite3`. PostgreSQL хранит состояние исходного дампа; изменения приложения в него не записываются.** Дополнительные возможности более новой PostgreSQL-версии код этой версии приложения не реализует.

Каталог `data/` подключён с хоста и сохраняется при пересоздании контейнера. Для резервной копии остановить приложение (`docker compose stop app`), скопировать весь `data/`, затем запустить (`docker compose up -d app`). `.env` и `data/` содержат секреты и исключены из Git и Docker build context.

Проверено: все контейнеры healthy, главная страница HTTP 200, API `/api/state` существующего профиля HTTP 200, `PRAGMA integrity_check` — `ok`. Пароли пользователей не менялись. Старые Redis-сессии отсутствуют в резервной копии; требуется повторный вход.
